# 牢络生成平台（顶栏「生成视频」）· 接入与替换说明

## 这是什么

用户提供的单文件网页「牢络生成平台公开版 · 优化 v2（LibTV 贝塞尔连线）」，
2026-11-17 由用户以文件形式发来（原件存档在用户文件区，接入副本即本目录
的 `source.html`）。工作台顶栏「生成视频」按钮点开的全页覆盖窗口里跑的
就是它：画布 + 卡片 + 贝塞尔连线、四线并行、角色/场景绑定、DeepSeek
一键转写、直连 autodl.art 的 ComfyUI 工作流 minimax_h3_zm_u24 生成
MiniMax H3 视频。平台功能与原件一致，工作台不改它的任何逻辑。

## 文件分工（平台本体保持单一独立单元）

- `source.html` —— 平台原件的接入副本，**替换新版时只换这一个文件**。
- `prepare.mjs` —— 构建期转换脚本（可重复执行）：读 `source.html`，
  做两件事后输出 `platform.html`：①把其中 `DEFAULT_TOKEN` 的值替换
  为空字符串（密钥剥离，幂等）；②把 `diagnostics.js` 的内容以内联
  `<script>` 注入 `<head>` 末尾（v6.50 起）。找不到 `DEFAULT_TOKEN`
  赋值语句或 `</head>` 时会报错停下，提醒先人工核对。
- `diagnostics.js` —— 工作台侧的加载诊断脚本源（不是平台本体）：
  跑在平台主程序之前，捕获平台的脚本报错 / CSP 违规、探查本机存储
  是否可用、观测 `#app` 是否真正渲染出来，全部通过 postMessage
  （channel `laoluo-diag`、build `v6.50`）报给 wrapper。为什么内联
  注入不用外联文件：打包后的资源名带内容哈希，`prepare.mjs` 在打包
  前运行算不出哈希，外联地址必然对不上；细节见该文件文件头。
- `platform.html` —— 自动生成的独立文档（不要手工编辑）：打包时作为
  assets 静态资源发出，wrapper 的 iframe 用 src 指过去加载（地址带
  build 缓存戳）。
- `../videogen.tsx` —— wrapper（与平台本体分离）：顶栏按钮总线 +
  全页覆盖窗口 + 同源 iframe 承载 + 关闭入口 + 打开时锁背景滚动 +
  防黑屏兜底（盯平台是否真的渲染出来、捕获平台 window.onerror，
  没打开时显示错误提示 + 「重试」）+ v6.50 起的加载诊断：四阶段
  （导航 → boot → 挂载观测 → app-ready）状态面板由 wrapper 自己的
  15 秒硬截止定时器驱动、与 iframe 事件无关，未确认渲染必出现，
  带「复制全部诊断 / 重新挂载 / 新窗口打开」三个按钮；覆盖窗头部
  另有「新窗口打开」按钮（window.open 同一平台地址，绕开嵌入层）。
  平台代码不进 wrapper，wrapper 不碰平台内部。

## 密钥口径（硬性）

- 已移除内嵌默认 Token：`source.html` 接入时 `DEFAULT_TOKEN` 已为空，
  且 `prepare.mjs` 每次转换都强制置空——换新版文件后只要跑一遍脚本，
  打包产物里就不会带任何内置 Token。Token 的值不得写进任何代码、
  注释、日志或文档。
- autodl Token 与 DeepSeek Key 由用户在平台右上角「密钥」对话框里
  各填各的，只存本机浏览器 localStorage（键名 `llpub-*`，与原件一致），
  不进工作台数据库、不进备份包。素材存浏览器 IndexedDB
  （`ll-platform-pub`），同样只在本机。
- 不填 Token 时平台是演示模式：只走流程、不出真视频、不花钱。

## 替换新版平台的流程（用户在 GPT 升级后发来新版文件时）

1. 用新版文件覆盖本目录的 `source.html`（只换这一个文件，
   不动工作台其他任何代码）。
2. 在本目录执行 `node prepare.mjs`，重新生成 `platform.html`
   （脚本会自动剥离新版里可能带的默认 Token，并自动注入
   `diagnostics.js` 诊断脚本——诊断脚本是工作台侧文件、随工作台
   仓库走，不在新版平台文件里，不用从新版里找；若脚本报错停下，
   先人工看一眼新版的密钥写法再处理，不要绕过）。
3. 重新构建工作台并验证：打开「生成视频」覆盖窗，确认画布渲染、
   建卡/连线/绑定、密钥对话框打开与保存、演示模式能跑完、
   关闭窗口回到工作台且工作台状态不受影响；再回读一遍工作台
   正式数据（达人/卡片/项目/记录等）确认与换版前一致。
4. 验证通过后上线。真实生成（填自己的 Token/Key 后出视频）只由
   用户本人在真机亲手跑，沙箱与构建流程永不代跑。

## 为什么用 iframe 独立文档地址承载（v6.49 起，v6.48 是 srcDoc）

平台原件大量使用内联事件属性（onclick 等）与全局函数、并直接操作
自己的 document；放进同源 iframe 后这些全部原样工作，且它的全局
样式（html/body 等）只作用于 iframe 内部，不可能影响工作台任何
现有页面。同源保证平台的 localStorage（llpub-*）、IndexedDB、
下载与剪贴板都正常。跨域已实测放行：autodl 与 DeepSeek 的预检
均允许浏览器直连，不需要服务端代理。

v6.48 曾用 srcDoc 把整份 HTML 当字符串塞进 iframe，真机全黑：
srcDoc 文档会继承宿主页面（工作台页面）的内容安全策略（CSP），
线上工作台页面的 script-src 不允许内联脚本，平台的那段内联
<script> 被浏览器整段拦下、界面永远渲染不出来，只剩平台自己的
黑底；沙箱审计环境没有这条 CSP，所以当时看着正常。改成独立文档
地址后，平台文档只受它自己响应头的策略约束。blob: 地址同样会
继承创建者的 CSP（实测一样黑），不要改回去。
